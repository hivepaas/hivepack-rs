# Extracting safely

`hivepack::extract` writes an archive's entries to disk, and is safe by default: nothing is written outside the destination, through a link, over what is there, or past limits set against archive bombs. It extracts ZIP archives that `hivepack::zip` opened, tar archives that `hivepack::tar` reads, cpio archives that `hivepack::cpio` reads (RPM packages' payloads among them), XAR archives that `hivepack::xar` reads (macOS packages and `.xip` files, their payloads expanded), ISO 9660 images that `hivepack::iso` reads, UDF volumes that `hivepack::udf` mounts, 7z archives that `hivepack::sevenz` opened and, with the feature `rar`, off by default as it takes UnRAR's license, RAR archives that `hivepack::rar` reads, with the same checks and the same writing.

Extractors no longer break on memory, which safe Rust settles, but on logic, and memory-safe code gets that wrong as often as C: writing through a link (the `zip` crate's CVE-2025-29787, adm-zip's CVE-2026-76845), keeping setuid bits or chmod through a link (RUSTSEC-2026-0367 and 0369), links that point outside (RUSTSEC-2026-0368), alternate data streams on Windows (WinRAR's CVE-2025-8088, exploited), and Python's tarfile filter, which took five CVEs in June 2025 for checking strings and `realpath`. The rules below answer those, and come from the research behind this repository's ZIP plan.

> **Status:** names, the same path twice, links, overlapping data, the limits, writing by handle, integrity, masked permissions and times, the options that relax them, a time limit, cancelling and progress, names compared as file systems compare them, and marks of origin: done, for ZIP, checked on libzip's test archives, Fifield's bombs, ZipDiff's archives, the archives behind sixteen CVEs (see [the table](#the-archives-behind-cves)) and Unicode's own tests, and fuzzed; and for tar (see [tar](#tar)), checked on Go's test archives and fuzzed; for cpio (see [cpio](#cpio)), checked on libarchive's test archives and fuzzed; for XAR and macOS packages (see [XAR](#xar)), checked on packages `pkgbuild` and `productbuild` make, against `pkgutil --expand-full`, and fuzzed; for ISO 9660 and UDF (see [UDF](#udf)), checked on libarchive's test images and on volumes Linux reads, and fuzzed; and for 7z (see [7z](#7z)), checked on archives 7-Zip makes and fuzzed. Next: RAR (see [What comes next](#what-comes-next)).

## Refuse, do not repair

Other extractors clean names up: Python drops `..` and drive letters, UnZip drops `../`. Two of them clean the same name differently (`foo/../bar` becomes `foo/bar` in one and `bar` in another), and that difference is itself an attack (ZipDiff, USENIX Security 2025). `hivepack::extract` refuses instead.

What leads outside the destination, or names nothing, is refused on every system, and stops the extraction: a leading `/`, a component `.` or `..`, an empty component. So is what Windows takes for a separator or a drive when Windows' rules apply, before it is anything else: `a\..\x` and `a.txt:..` climb (`NameError::Dot`).

The rest is what a system cannot name, and depends on `Options::name_rules`:

- `NameRules::Native`, the default: this system's rules. Windows' characters, device names and ends of names are refused on Windows only, so that `a:b.txt`, `aux.txt` and `what?.txt` extract on Linux and macOS as they are; and two names that differ only in case, or in how their Unicode is composed, are one path only where the destination's file system takes them for one. That is found before anything is written: a file is made in the destination (or the nearest folder above it that is there), looked for by its name in the other case and the other composition, and taken away; if it cannot be, Windows and macOS are taken to fold and the others not. So a case-sensitive APFS volume takes `README` and `readme`, and a USB stick in exFAT on Linux does not. A control character, or a component longer than 255 bytes, is refused everywhere. A `Sink` takes both of two such names, and any name at all but one that leads outside on some system, on every system: what it makes is an archive, not a folder ([below](#into-something-other-than-a-folder)).
- `NameRules::Portable`: every system's rules, wherever it runs (`check_name`), so that an archive extracts the same everywhere or not at all. It is what the tables below and the tests are written for.

A name refused only as one the system cannot take (`NameError::is_unnamable`) can be asked about: `Options::on_unnamable` is told all of them at once, before anything is written, with the names the system takes for others', and answers to stop, leave them out (`Summary::skipped`) or rename them (`Summary::renamed`). Renamed, what cannot be in a name becomes `_` (`a:b.txt` → `a_b.txt`), a device name gets a `_` before it (`_aux.txt`), a space or dot at the end becomes `_`, a part too long is cut down with its extension kept, a folder spelled another way takes the spelling already there (`docs/b.txt` → `Docs/b.txt`), and a name already taken is numbered (`readme (2)`). A name that leads outside is never asked about.

By every system's rules (`NameRules::Portable`), a name is refused (`check_name`, `NameError`) when it:

| Has | Because |
|---|---|
| nothing, or an empty component (`a//b`) | |
| bytes that are not UTF-8, once decoded from CP437 for a name without the UTF-8 flag | |
| a control character (U+0001 to U+001F, DEL) or NUL, in the decoded name or the raw bytes | libzip decodes CP437 0x01 as ☺; an extractor that takes the bytes as they are sees a control character |
| a backslash | Windows takes it for a separator |
| a leading `/` | absolute |
| a colon | a drive (`C:`), or an NTFS alternate data stream (`a.txt:hidden`) |
| `<`, `>`, `"`, `\|`, `?` or `*` | Windows does not allow them in names, so an archive that has them extracts on Linux and fails half way on Windows |
| a component `.` or `..` | climbs out |
| a Windows device name, with or without extension, in any case: `CON`, `PRN`, `AUX`, `NUL`, `COM0`–`COM9`, `LPT0`–`LPT9`, `COM¹`–`COM³`, `LPT¹`–`LPT³`, `CONIN$`, `CONOUT$` | names a device in every directory |
| a component ending in a space or a dot | Windows drops them, so `a.` and `a` are one file |
| a component longer than 255 bytes | file systems refuse it |

Two entries may not name the same path either: compared as a case-insensitive file system, and macOS, compare them, which stops a file and a directory of one name (WinRAR's CVE-2023-38831), a path written through another's case, and one name written two ways. A directory entry may follow the files in it.

Names are compared by their key, Unicode's canonical caseless match (definition D145): NFD(fold(NFD(name))), the canonical decomposition of the full case folding of the canonical decomposition. So `é` as one character (U+00E9) and as `e` and a combining accent (U+0065 U+0301), which macOS takes for one name and Linux for two, are one name here; and so are the Kelvin sign and `K`, one by canonical decomposition as macOS takes them, `σ` and `ς`, one by case folding as NTFS takes them, and `ß` and `ss` or the ligature `ﬁ` and `fi`, which macOS folds into one (its CI run found it: it refused `fi` after `ﬁ`). Each system joins some of these, and the key joins all of them, so that an archive extracts the same everywhere or not at all. Compatibility forms that do not fold stay apart: the fullwidth `Ａ` is not `A`, nor `①` `1`. Without the check, a second name written another way stops the extraction at its write, as `Exists`, after the first is written; with it, before anything is.

The tables are this crate's own, in safe Rust, for one Unicode version on every system (`UNICODE_VERSION`, 18.0.0), rather than the standard library's, whose version moves with Rust, or `unicode-normalization`, which has `unsafe` code. `scripts/unicode.py` makes them from the Unicode Character Database (`UnicodeData.txt` and `CaseFolding.txt`, the `unicode-18.0.0` test data set); the tests check them against the same files for every character, run Unicode's own `NormalizationTest.txt` (20,171 lines, and every character it does not list decomposing to itself), and check that a key is its own key. Raising the version is changing it in the script and the manifest, and running the script.

## Links and special files

Symbolic links (from the Unix mode of the external attributes) are refused, unless the options say otherwise.

A device, FIFO or socket in a ZIP archive is only a mode with data: Info-ZIP's `zip` records the mode of what it reads, a pipe for standard input (the entry `-` of libzip's `streamed.zip` and `zip64.zip`). Such an entry is written as a file with its data; nothing is ever created as what the mode says.

## Writing by handle

Checking a path and then writing to it lets a link put in between be followed. Every write goes through handles instead: the destination is opened once, each directory under it is opened from its parent's handle without following a link, and each file is created new (`O_CREAT|O_EXCL`, `O_NOFOLLOW`; `CREATE_NEW` on Windows). So a link already in the destination, or one put there while extracting, is not followed: a directory on the way that is a link stops the extraction (`NotADirectory`), and so does a file that is there (`Exists`). Nothing is overwritten.

The standard library cannot do this yet: its directory handles (`std::fs::Dir`) are not stable. cap-std does it, with `openat2` and `RESOLVE_BENEATH` on Linux 5.6 and later, `openat` with `O_NOFOLLOW` a component at a time elsewhere on Unix, and handles relative to a directory's on Windows; it is a dependency with `unsafe` code, in this crate only (see [safety.md](safety.md#dependencies-with-unsafe-code)), and `std::fs::Dir` replaces it once stable.

The destination itself is the caller's: it is created if it is not there, and its path is followed as given.

## Limits

An archive's sizes are what it says, and archive bombs say what gets them past a check: adm-zip believed them three times in 2026 alone. `Limits` count what is actually written:

| Limit | Default | |
|---|---|---|
| `max_entries` | 100,000 | counted before anything is read |
| `max_entry_size` | 4 GiB | |
| `max_total_size` | 16 GiB | |
| `max_ratio` | 2,000 | bytes written for each compressed byte, once an entry has written `ratio_threshold` (1 MiB). Deflate tops out near 1,032 to one, which a file of zeros reaches, so this stops only methods that go further: Deflate64, and bzip2, LZMA, XZ, Zstandard and PPMd, whose files of zeros reach far beyond it and need a higher limit |

The sizes the archive declares are checked against the limits before anything is written, then the data is counted as it comes, and an entry stops as soon as it passes a limit or the size it declared (`SizeMismatch`). Nothing is allocated from a declared size.

Entries whose compressed data overlap are refused before anything is written. That is how David Fifield's bombs work, 42 kB to 5.5 GB or 46 MB to 4.5 PB with Zip64: many entries, one stream. The data ranges are sorted and each compared with the one before, which catches the "quoted" form too, whose entries each hold the next one's header.

The defaults are a judgment, to be tuned on real archives; each can be raised.

## Integrity, permissions and times

Every entry's data is checked at its end, its CRC-32, or for WinZip AES its authentication code, by `hivepack::zip`; a file whose data fails is removed, as is one cut off at a limit, and the extraction stops. Encrypted entries are read with `Options::password`.

On Unix, a file gets the permission bits its entry has, masked as Python's `data` filter masks them: no setuid, setgid or sticky bit, nothing writable by group or others, and readable and writable by its owner. Owners, ACLs and extended attributes are not restored. Directories get the system's default permissions. Files and directories get the time their entry has, the directories once nothing more is written in them, the deepest first, without following a link. A time the system cannot hold (after January 2038 where `time_t` has 32 bits) is left: the file keeps the time it was written at.

## Marks of origin

A downloaded archive carries a mark of where it came from, which the system checks before a file is opened or run: Windows' Mark of the Web, a `Zone.Identifier` stream with the zone (`ZoneId=3` for the internet) and the address, and macOS's quarantine, the `com.apple.quarantine` attribute that Gatekeeper reads. A file extracted without it escapes the check: 7-Zip's CVE-2025-0411, exploited, was nested archives losing it.

`Origin::of` reads the mark an archive's file has, and `Options::origin` carries it, as it is, to every file written: on Windows the stream is opened from the file's own handle (`:Zone.Identifier` relative to it, so no path is resolved again, and a file named `a` is not taken for drive A); on macOS the attribute is set on the file's descriptor, and on every directory created too, as Gatekeeper checks an app, which is a directory. The mark is written before the file's time, which writing a stream changes. A mark that cannot be written stops the extraction (`ErrorKind::Origin`), and so does one this system cannot carry, before anything is written: an extraction that drops the mark would hide where its files came from. It is not the default only because the archive's path is the caller's: `extract_zip` reads an `Archive`, not a file.

`Origin::without_addresses` gives the mark without what a download left in it to say where its user has been, for an app that would rather not copy that on to every file: Windows' stream keeps only its zone, and one with no zone that can be read says the internet, as a mark must not be lost by being odd. macOS's holds no address and stays as it is.

Linux and the other systems have no mark (`Origin::of` gives `None`). macOS's attribute takes `rustix`, a dependency with `unsafe` code, already there for `cap-std`, since the standard library has no extended attributes (see [safety.md](safety.md#dependencies-with-unsafe-code)).

## Time, cancelling and progress

The limits bound what an archive writes, not how long it takes: a disk that is slow, or many small entries, take their time within them. `Options::time_limit` (none by default) stops an extraction once past it, from when it starts (`ErrorKind::TimeLimit`), and `Cancel`, a token whose clones share one flag, stops it from another thread (`ErrorKind::Cancelled`). Both are checked between entries and before each read of data, which gives at most 64 KiB; a read of compressed data that gives nothing, such as empty Deflate blocks, runs to the end of that entry's data, which the archive's size bounds. A file cut off is removed, as one whose data fails; what was written before stays.

`Options::progress` is told the entries and bytes to write once the entries are checked, as the archive says them (the data is checked against them, so what is written does not pass them), then the entries and bytes written after each piece of data and each entry. It is called on the extracting thread (with [threads](#threads), on the one that wrote, one call at a time), and should hand on what it is told, not wait. Calling `Cancel::cancel` from it stops the extraction.

The research behind this plan found neither in any Rust ZIP crate, so the design is this crate's own: a token and a function, rather than an asynchronous interface, as the writing blocks anyway.

## Options

Each rule that is not about writing outside the destination can be relaxed, by name (`Options`):

| Option | Default | Otherwise |
|---|---|---|
| `links` | `Links::Refuse` | `AsFile`: a file holding the target, as extractors on Windows write links. `Inside`: links whose target is relative and stays inside the destination by its text (`..` allowed, as long as it does not climb out), and does not pass through another link of the archive, which the system would follow where the text does not; read and checked before anything is written, and created after every other entry, so nothing is written through them. On Windows, creating a link takes a privilege that most accounts lack. `Any`: every link, its target as the archive has it, absolute or leading outside too, as tar creates them, for archives that are trusted (a backup of one's own files): created last as with `Inside`, so nothing is written through them, and a path under a link is still the link's (`Duplicate`); a target that is no path is refused, and on Windows, into a folder, one from a root or a drive, which cap-std does not create |
| `name_rules` | `NameRules::Native` | `Portable`: every system's rules, wherever it runs (see [Refuse, do not repair](#refuse-do-not-repair)) |
| `on_unnamable` | none: as `on_refused` | A function told, once and before anything is written, every entry whose name this system cannot take, which answers to stop, leave them out or rename them |
| `links_outside` | `OnRefused::Stop`, as `on_refused` | `Skip`: a link whose target leads outside or through another link is left out, whatever `on_refused` says |
| `on_links_outside` | none | With `Links::Inside`, asked once, before anything is written (after `on_unnamable`), about the links whose targets lead outside or through another link, each with its target (`LinkOutside`): `Stop`, `Skip` (left out, in `Summary::skipped`) or `Create`, as `Links::Any` creates them. A target that is no path (empty, not UTF-8, a control character) is not asked about: it is refused as `links_outside` says |
| `names` | `Names::Strict` | `Sanitize`: first drops what Python's `zipfile` drops, a leading `/`, a drive (`C:`, a letter and a colon, as Windows reads it) and `.`, `..` and empty components, then refuses what is still refused |
| `backslash_separator` | `false` | `\` taken for a separator, as PowerShell 5.1's `Compress-Archive` writes it |
| `select` | none: all entries | Extracts only the entries a function picks by path; the others are not checked, counted or written, and data a picked entry depends on in a solid block is still read |
| `decode_names` | none: ZIP reads CP437, the others refuse | A `NameDecoder` makes text of names that are not UTF-8, told the bytes and what the format reads them as; `NameDecoder::lossy()` keeps that, or else puts U+FFFD for what is not UTF-8. Its text is checked as any name is |
| `on_damaged` | none: stop | A function told each entry whose data is damaged, which answers to stop, leave it out or keep what was read of it (see [Damaged data](#damaged-data)) |
| `on_refused` | `OnRefused::Stop` | `Skip`: an entry refused for its name, as a link or as the same path as another is left out, listed in `Summary::skipped` with its reason, and the rest extracted. The limits and overlapping data still stop the extraction: they are about the archive, not one entry |
| `overwrite` | `false` | Files that are there are replaced, if they are files: opened without following a link and emptied. A link or a directory there still stops it |
| `permissions` | `Permissions::Masked` | `Preserve`: the entry's bits but setuid, setgid and sticky. `Ignore`: the system's |
| `limits` | see [Limits](#limits) | each raised or lowered |
| `password` | none | the password encrypted entries are read with |
| `origin` | none | the archive's mark of origin (`Origin::of`), carried to every file (see [Marks of origin](#marks-of-origin)) |
| `time_limit` | none | how long the extraction may take (see [Time, cancelling and progress](#time-cancelling-and-progress)) |
| `cancel` | none | a `Cancel` token that stops it |
| `progress` | none | a function told how far it is |
| `threads` | `Threads::One` | how many threads extraction may use: files written at once where the archive's entries are apart (ZIP, RAR that is not solid), LZMA2 blocks decompressed at once in 7z (see [Threads](#threads)) |
| `memory_limit` | none | the memory the threads may take where each holds what it decompresses with (RAR): the threads are lowered until they fit, one always allowed (see [memory.md](memory.md#readers)) |
| `memory_budget` | none | with the feature `memory`, a `memory::Budget` the threads' memory is held from once it is known, after the first reading, until the extraction is done |

## Damaged data

By default an entry whose data is damaged stops the extraction, the entry removed, as any error does. `Options::on_damaged` is asked instead, on the extracting thread (with [threads](#threads), on the one writing the entry, about one entry at a time), for each such entry, and answers `OnDamaged::Stop`, `Skip` (left out, and on to the next) or `Keep` (what was read of it kept, as it came, and on to the next). The entries gone on from are in `Summary::damaged`, each with its error and the bytes kept.

Only damage is asked about (`ErrorKind::is_damage`): data that fails its check (a CRC-32, RAR's hash, WinZip AES's authentication code), cannot be decompressed, ends before the size the archive says, or cannot be read from the archive. Everything else stops whatever the answer: names, the same path twice, links, devices, the limits, overlapping data, an archive that changed between its readings, the destination, a cancel or the time limit, and a wrong or missing password, which is for the caller to ask for again. A kept file holds no more than its entry says, and counts against the limits as any file.

What can be gone on to depends on the format:

| Format | After a damaged entry |
|---|---|
| ZIP, UDF | the next entry, read on its own |
| RAR | the next entry; in a solid stream what follows may fail too, and is asked about in turn |
| XAR | the next entry, if the archive reads on from there; one cut short stops the extraction |
| 7z | the next file, if its folder's stream is whole (a CRC that fails); otherwise the rest of that folder is lost, each of its files asked about and left out, and the next folder read |
| tar, cpio, ISO 9660 | the stream is read in order: one cut short, or that cannot be read on from a place, is extracted up to there. The first reading stops there too, rather than stopping the extraction, so the entry the stream ends in is asked about when the second reading gets to it; a stream that ends between entries is asked about once, with no entry's name |

A `Sink` is told with `Sink::damaged`, before `finish_file` (kept) or `discard_file` (left out).

## Threads

An extraction writes one file at a time, on the caller's thread, by default. `Options::threads` (`hivepack::Threads`: `One`, `Auto` for as many as the machine runs at once, or `Exactly(n)`) lets it use that many threads, where the archive lets the work be split:

- **ZIP**: each entry's data is read on its own, by position, from where the central directory says. Once every entry is checked, and the directories are made on the caller's thread in the archive's order, each thread takes the next file and writes it whole, straight from the archive into the file: as many files are open, and as many pieces of data held, as there are threads, and nothing more is kept. Links are created after every file, and the directories get their times last, as with one thread. Every thread reads the archive at once, so `extract_zip` asks its source to be `Sync`, as a `File`, `Volumes` or a slice are. On a machine of 32 threads, 20,000 text files of 400 MB in all, deflated to 130 MB, extract onto ext4 in 1.16 s on one thread, 0.61 s on two, 0.34 s on four, 0.19 s on eight and 0.08 s on all.
- **RAR**: an archive that is not solid has its files written at once, each by a thread that opens the archive itself (each thread calls `open` once to go through it, and once more if it takes large files first, so `extract_rar` asks it to be `Fn` and `Sync`) and goes through its headers, writing the files no other thread has taken and passing over the rest. The directories are made first, on the caller's thread, and hard links, file copies and links written as files after the files, in the archive's order. Files larger than a share of what all write (half of the whole for each thread) are taken first, largest first, each by a thread going to its header, so that one met last in the archive is not left to one thread at the end; in an archive of many volumes, whose places are in their own volumes, they are taken in order. Each thread holds a window as large as the archive's dictionary asks, as UnRAR does, so the threads are lowered to fit `Options::memory_limit` and `Options::memory_budget` ([memory.md](memory.md#readers)). A solid archive, whose entries go on from one another, is read on the caller's thread. On a machine of 32 threads, 22,540 files of 343 MB in 3,714 directories (`/usr/include`, `/usr/share/doc` and a Python library, RAR 5 `-m3`) extract into tmpfs in 1.18 s on one thread, 0.66 s on two, 0.41 s on four, 0.28 s on eight and 0.22 s on sixteen; with three files of 125 MB after them, in 1.37 s on one and 0.30 s on eight. What is left on the caller's thread, the first reading and its checks, the directories and their times, takes most of the rest. Silesia's 12 files, 211 MB, take 0.47 s on one thread and 0.15 s on four or more: as long as its largest file, `mozilla`, takes alone.
- **7z**: the folders, each a solid block or a file of an archive that is not solid, are decoded at once, each by a thread that writes its files, in the archive's order within the folder; the largest folders are started first. The directories and the files without data are made first, on the caller's thread, which then reads the archive for the threads, a piece of 64 KiB at a time as each asks: so `extract_7z` takes the same `Read + Seek` archive as before, and reads it from one thread. Each thread holds its folder's decoder, whose dictionary or model the archive says (LZMA's up to 1.5 GiB as 7-Zip writes it, PPMd's model up to 4 GiB), so the threads are lowered to fit `Options::memory_limit` and `Options::memory_budget` ([memory.md](memory.md#readers)). The threads left over, and those whose folders are done as the last ones are decoded, decompress LZMA2 whose stream resets its dictionary on the way, as 7-Zip writes it in threads and `sevenz::Lzma2Blocks` does, a block in each ([7z.md](7z.md#lzma2-in-blocks-in-threads)): a folder decoded alone takes all of them, as before. Times below.
- **Into a `Sink`**, entries are given one at a time, in order, on the caller's thread, whatever this says.

What is written is the same whatever the threads: the files, their bytes, modes and times, and the `Summary`, with `Summary::damaged` in the archive's order (in 7z, damaged LZMA2 in blocks behind a filter may fail a file later in threads, as [7z.md](7z.md#lzma2-in-blocks-in-threads) says). The threads share what is counted and told: the limits count what they all write, `Options::progress` is told by the thread that wrote, one call at a time, so that what it is told never goes back, and `Options::on_damaged` is asked about one entry at a time. A cancel or the time limit stops every thread between pieces of data, and so does the first error, which is the one returned: the others remove the files they were writing, as a file cut off is removed. What is left after an error is what differs: with one thread, nothing after the entry that failed; with more, files after it in the archive may have been written.

A single solid block, as 7-Zip writes by default up to 2 GB, is decoded as before, its blocks in every thread; with several, the threads left over, and those of the folders done, decode their blocks.

## Into something other than a folder

Each extractor has a twin that writes into a `Sink` in place of a folder: `extract_zip_to`, `extract_tar_to`, `extract_7z_to`, `extract_rar_to`, `extract_cpio_to`, `extract_xar_to`, `extract_iso_to` and `extract_udf_to`. A sink is what converts an archive to another format, entry by entry, without a folder in between: one that writes an archive, an index, a checksum of each file. Both go through the same code, so the sink is given what the folder would get, after the same checks, in the same order, and nothing it is not:

- **What is given.** Directories, files and the links `Options::links` keeps, each with its path, checked as names are (so a sink never sees `..`, an absolute path, or two entries of one path), its time, and its permission bits as `Options::permissions` has them. A directory on the way to an entry is given only if the archive has an entry for it.
- **Files** come as `start_file`, their data in pieces as it is decoded, then `finish_file`; nothing more of an entry is held than the piece being given. The limits count what is given, as they count what is written. A file whose data fails its check is ended with `discard_file`, and the extraction stops with its error.
- **Links**: symbolic links come after every other entry, as they are created; a hard link after the file it names, as one, whatever `Options::links` says, since what was given cannot be read back to copy. For the same reason a RAR file copy fails here (`ErrorKind::Io`, `Unsupported`).
- **Names**: by this system's rules (`NameRules::Native`), a sink is given any name its archive can hold, on every system, Windows too: `ab:c.txt`, `aux.txt`, `what?.txt`, a name ending in a dot, a component longer than 255 bytes, and two names that differ only in case. Only what leads outside where the archive made is extracted, on any system, is refused: `..`, with `\` and `:` taken to split a name as Windows takes them (`a\..\x`), and `/`, `\` or a drive (`C:`, `a:b.txt`) at its start; and control characters. `NameRules::Portable` keeps every system's rules, as for a folder.
- **What a folder only has**: holes, files already there, and marks of origin. A sink is given zeros, `Options::overwrite` and `Options::origin` do nothing, and carrying a mark of origin to what the sink makes is the caller's.
- **Errors**: an error a sink returns stops the extraction, as `ErrorKind::Io`, the destination's error.

## tar

A tar archive has no central directory: each header comes before its data, one after the other, often inside a compressor (`.tar.gz`, `.tar.zst`) or age (`.tar.zst.age`). To check every entry before anything is written, as for ZIP, `extract_tar` reads it twice, through a function that opens it again (and so decompresses or decrypts it again): first the headers, the data skipped, for every check of the plan; then the entries are written, each header compared with the first reading's, its type, name, link target and size, and an archive that is not the one checked stops (`ErrorKind::Changed`) at the first that differs, or where the readings end differently. Data cut short stops the first reading, before anything is written; a file whose data fails in the second is removed.

What differs from ZIP:

- **`./`**: `tar -cf x.tar .` writes every name with a leading `./`, which is dropped; `./` itself, the archive's root, is not an entry. Every other `.` component is refused, as in ZIP.
- **Symbolic links** take their target from the header, not the data; the options are ZIP's.
- **Hard links** are a second name for a file the archive extracted before them: the target, a name in the archive (`./` dropped, the same rules), must be such a file, kept and earlier, or the link is refused (`ErrorKind::HardLinkTarget`, or `LinkTarget` for a target refused as a name). So a hard link can neither lead outside nor reach a file that was there before. It is created as a hard link inside the destination, by handle; with `Links::AsFile`, as a copy, which counts against the limits as written data.
- **Devices and FIFOs** have no data in tar, only what to create, and nothing is created as one: they are refused (`ErrorKind::Special`), or left out with `OnRefused::Skip`.
- **Global PAX headers and GNU volume labels** describe the archive, and are not entries. GNU's dump directories (`D`) are directories; every other type is a regular file, as GNU tar and Python take them.
- **Sizes**: tar does not compress, so there is no ratio to check here; the compressor's ratio is its own. A sparse file's holes stay holes where the file system has them: what reads as zeros in a sparse entry is not written, in a file that is new or emptied. They still count against the limits, as they are what the file comes to. On Windows the file is not marked sparse, which takes a call that safe Rust does not have, so its holes take room there.
- **Every entry counts against `max_entries`**, metadata too, so that an archive of global headers does not grow the first reading's list without end.
- **The stream is read to its end.** A tar reader stops at the archive's end, but a compressor checks its data at the end of its stream (gzip's and bzip2's CRC-32, xz's and zstd's checks), and age authenticates its last chunk there. Each reading goes on to the end, as GNU tar reads its compressor's output to the end, so that a stream that fails its check fails the first reading, before anything is written (`ErrorKind::Io`). What follows the archive's end is limited to `max_total_size`, or 1 MiB if that is less, the largest record tar pads to. [open.md](open.md) opens archives through those layers.

## cpio

`extract_cpio` extracts the cpio archives `hivepack::cpio` reads: Linux's initramfs images, RPM packages' payloads (taken out of the package and decompressed by [open.md](open.md)'s layers), and what `cpio` writes. As tar's, an archive is a run of headers each before its data, so it is read twice, through a function that opens it again, each header compared with the first reading's (all of it). The first reading skips the data, which reads it through: an archive cut short, or without `TRAILER!!!`, stops it before anything is written. cpio has no checksums to check but crc's, which libarchive does not check either.

What differs from tar:

- **`.`**, the root directory, is not an entry (`find . | cpio` writes it); names drop a leading `./`, with every rule of [the names](#refuse-do-not-repair).
- **Entries after garbage** come from `hivepack::cpio` with libarchive's warning, "Skipped N bytes before finding valid header": what was passed over is lost. They are refused (`ErrorKind::CpioEntry`), or left out with `OnRefused::Skip`. libarchive's search goes through what cannot be a header six bytes at a time, and finds a newc header only where it lands on it: after other garbage, the archive reads to its end without the header, and fails there.
- **Hard links** are the entries libarchive gives as another name for an earlier one (the same device and inode), and a file's data comes with any of its names: with the last in newc, as GNU cpio and RPM write it, the others empty; with each in odc. libarchive's extraction writes each entry's data into the file the names share, so that it holds the last data written. Here the file is written once, under its first name, when the last of its entries with data comes; its other names are then linked to it, or copied with `Links::AsFile`, and those that come after it as they come. The limits count the file once, at the size of that data, before anything is written.
- **Devices, FIFOs and sockets** are refused (`ErrorKind::Special`), as tar's: an initramfs image's `/dev/console` among them, which `OnRefused::Skip` leaves out.

## XAR

`extract_xar` extracts the XAR archives `hivepack::xar` reads: macOS packages (`.pkg`), `.xip` files and what `xar` makes. libarchive reads a table of contents, then each file's data where it is in the heap, in order, as from a stream: an archive is read twice, as tar's, through a function that opens it again, each header compared with the first reading's. The first reading reads each file's data to its end, where its checksums are checked: a file damaged anywhere stops the extraction before anything is written.

**A package's files are in its payloads**, not its entries: cpio archives, under gzip or pbzx, named `Payload` in each component package (`Scripts` for its scripts), and `Content` in a `.xip` file. With `Packages::Expand`, the default, an entry of one of these names whose data opens, through its layers ([open.md](open.md)'s `Opener`, over the XAR reader), to a cpio archive becomes a directory of that name with the archive's files, as `pkgutil --expand-full` does (which `xip --expand` does not: it writes a `.xip` file's content in place). Each payload is planned in the first reading, as `extract_cpio` plans an archive: its names, links and limits checked with the rest, so that a payload with a name that climbs out, or one cut short, stops the extraction before anything is written. The limits count every payload's entries and bytes with the XAR archive's. An error in a payload names its entry's index, and the path in the payload after the payload's own (`Payload/./../escape`). `Packages::AsFiles` writes the payloads as they are.

What differs from tar:

- **Entries libarchive gives with a warning** (a name that is not UTF-8) are refused (`ErrorKind::XarEntry`), or left out with `OnRefused::Skip`; so is an entry whose data is before the place read to (`hivepack::xar::Error::CannotSeek`), which a stream cannot go back to, as libarchive's reader gives it (`ARCHIVE_FAILED`, after which it goes on).
- **Hard links** are the entries libarchive gives as another name for an earlier file; **symbolic links**, devices and FIFOs as tar's. Owners, file flags and extended attributes (macOS's quarantine among them) are not restored: the mark of origin is the destination's own (`Options::origin`).
- **Directories** without a mode, owner or time are not entries, as libarchive leaves them out: they are created on the way to what they hold.

## ISO 9660

`extract_iso` extracts the ISO 9660 images `hivepack::iso` reads (CD and DVD images, Linux installers, `.iso.xz` through [open.md](open.md)'s layers), as `extract_tar` extracts tar: an image is read in order, as libarchive reads one without seeking, so it is read twice, through a function that opens it again, each header compared with the first reading's (all of it: path, mode, owner, times, links, size). The first reading reads each file's data too, up to its size, and drops it: skipping it would read it anyway from an input that cannot seek, and so data cut short or damaged (a zisofs block that does not decompress) stops the extraction before anything is written, where tar's first reading finds only what precedes the last header.

What differs from tar:

- **`.`**, the root directory, is not an entry. Names are Rock Ridge's, else Joliet's in UTF-8, else ISO 9660's without their `;1`, with every rule of [the names](#refuse-do-not-repair): a Rock Ridge name is any bytes, `../escape` included.
- **Entries with something missing** come from `hivepack::iso` with a warning, libarchive's `ARCHIVE_WARN`: a directory left out with all it holds (before the place read to, or past the image's end), a file past the image's end, a file whose data is before its directory (which an input that cannot seek cannot go back for), a Joliet name or link target that is not UTF-16. They are refused (`ErrorKind::IsoEntry`), or left out with `OnRefused::Skip`, as a refused name is. A part of a file's data out of place, found while reading it, stops the first reading.
- **Hard links** are the entries libarchive gives as a second name for the file before them (the same serial number): created as tar's are, or copied with `Links::AsFile`.
- **Devices, FIFOs and sockets** from Rock Ridge are refused (`ErrorKind::Special`), as tar's.
- **Permissions**: an image without Rock Ridge has none, and libarchive's 0400 and 0700 are its own, so its files and directories get the system's defaults; Rock Ridge's are masked as ZIP's and tar's.
- **Sizes**: a file is written to its size. A zisofs file's data, as libarchive gives it, can stop before (the blocks of zeros at its end are left out) or, damaged, go on past it: the file is made its size with zeros, and what is past it is not read, as libarchive's extraction (`archive_write_disk`) does. zisofs's compression is not counted against `max_ratio`, as the image does not say how much each file takes; the limits on sizes stand.

## UDF

`extract_udf` extracts the UDF volumes `hivepack::udf` mounts (DVD, Blu-ray and Windows' images, which [open.md](open.md) tells, with ISO 9660 beside UDF or not). A volume is read by random access, as a ZIP archive is, so it is read once: its tree is walked first, parents before what they hold, every node read, every file's data checked to be on the image without reading it (`Udf::check_data`), every link's target read, and every entry checked, before anything is written; then the files are written, each read where it is. The caller mounts the volume: `hivepack::udf::Options::unhide` lists the entries a volume hides (Windows marks hidden files so), which NetBSD and Linux leave out, as `extract_udf` then does.

What differs from tar:

- **The root directory** is not an entry, and `..` is not either. Names are the volume's, translated as NetBSD translates them for UNIX (a slash or NUL becomes `_`, then the name ends with `#` and its CRC), with every rule of [the names](#refuse-do-not-repair): a name in a character set other than OSTA's is its bytes, refused if they are not UTF-8.
- **What cannot be read is refused** (`ErrorKind::Udf`): an entry whose node, data or link target does not read (an image cut short, allocation descriptors that do not cover a file, a link recorded as text, as macOS's `hdiutil` records them), and a directory with a broken entry, whose entries after it are missing; or left out with `OnRefused::Skip`, but a broken root directory, which stops the extraction. Everything is found before anything is written, so an image cut short in a file's data stops the extraction with nothing written.
- **Hard links** are the entries that name a node another entry named first: created as tar's are, or copied with `Links::AsFile`. A directory named twice, or its own ancestor, which UDF does not allow, is refused (`ErrorKind::DirectoryAgain`), and its tree is not walked again.
- **Devices, FIFOs and sockets** are refused (`ErrorKind::Special`), as tar's, and so are the nodes NetBSD gives no type.
- **Sizes**: a file is written to its size; what is not recorded (a sparse file's holes) is zeros, and counts against the limits. A volume does not compress, so there is no ratio to check, and a file's extents are not compared with others': many files on the same blocks write no more than the limits let them.

## 7z

`extract_7z` extracts the 7z archives `hivepack::sevenz` opened. A 7z archive lists every entry in its headers, as a ZIP archive does, so every entry is checked before anything is written, with ZIP's rules. Its data is in folders, streams that may each hold many files (a solid block), which are decoded once, from start to end, with `Archive::files`: each file is written as its data comes, counted against the limits, and checked against its CRC when it ends; each folder's own checks come when its last file is read, and the last folder's after the last entry, written or not. A file whose data fails is removed, and the extraction stops there, as in ZIP. The caller opens the archive: one whose headers are encrypted needs the password then (`hivepack::sevenz::Options::password`); `Options::password`, as UTF-8, is the one the data is decrypted with. 7z has nothing to check a password with but the data, so a wrong one is a CRC that fails (`hivepack::sevenz::Error::WrongPassword`).

What differs from ZIP:

- **Names** are UTF-16 in the archive: one that does not decode is refused (`NameError::NotUtf8`), not guessed. 7-Zip writes `/` between components on every system and keeps a `\` of a Unix name as it is, which Windows' rules refuse as in every format (`backslash_separator` takes it for a separator).
- **Links** are the entries whose attributes hold the Unix mode of a symbolic link (7-Zip's `-snl`), their target their data. With `Links::Inside`, the targets are read first, decoding the folders up to the last link once more, and checked as ZIP's are; with `Links::AsFile` they are files holding their targets.
- **Devices, FIFOs and sockets** are only their mode with data, as in ZIP: written as files.
- **The ratio**: a file's compressed size is its share of its folder's packed streams (`Archive::folder_packed_size`, by its unpacked size), so that a file is held to its folder's ratio. Folders do not share packed streams, so there is no overlap to check.
- **Permissions** are the Unix mode 7-Zip keeps in the high bits of the attributes (bit `0x8000` set), masked; an archive made on Windows has none, and its files get the system's defaults. The time is the modification time, an NTFS time.
- **Threads**: with `Options::threads`, folders are decoded at once, each by a thread that writes its files ([Threads](#threads)), and the threads left over decode LZMA2 whose stream resets its dictionary on the way, as 7-Zip writes it in threads and `hivepack::sevenz::Lzma2Blocks` does, a block in each, for this extraction (`Archive::set_threads`). What is written is the same. Damaged data fails the same way, but with a filter after LZMA2 (BCJ), which one thread reads 64 KiB ahead of the files, the error may come a file later in threads, the files before it whole and right (see [7z.md](7z.md#lzma2-in-blocks-in-threads)). Into a `Sink`, the folders are decoded one after another, LZMA2's blocks still in threads.

## Errors

An extraction stops at the first entry refused (unless `on_refused` is `Skip`), with its index, its name as the archive has it, and the reason (`Error`, `ErrorKind`). What is checked before writing (names, the same path, links, overlaps, declared sizes) stops it before anything is written, the destination included.

Each archive is damaged 40 ways, a bit changed or cut short, and extracted with each choice of links, skipping or not: nothing outside the destination, and no file left cut off.

`crates/hivepack/tests/extract_sevenz_threads.rs` extracts 7z archives with 1, 2, 8 and all threads, and finds the same files and the same summary each time: a folder a file, of every method the writer has (LZMA2, LZMA, BZip2, Deflate, stored), with directories, empty files and links, with links as files and with some entries picked; solid blocks with LZMA2 in blocks within them, encrypted too; and `testdata/7z`'s archives. Five damaged folders out of 24, gone on from or kept, give the same `Summary::damaged`, in the archive's order; without `on_damaged` the extraction stops, and no damaged file is left. A wrong password, the total limit and a cancel stop every thread. Under a memory limit no more threads write than fit, and with the feature `memory` a budget is held and given back. `tests/memory_limits.rs` checks what the threads hold against their estimate ([memory.md](memory.md#readers)).

The `extract` fuzz target (see [fuzz/README.md](../fuzz/README.md)) extracts its input with options its first byte picks, cancelling it after some progress if that byte says so, and checks that nothing is written beside the destination, that every link created stays inside it by its text, that the summary counts what is there, and, however the extraction ends, that the files left hold exactly the bytes of the entries written in full, so that none is left cut off. 11 million inputs over four minutes found nothing before the first commit, and 9.6 million with cancelling; with the removal of a failed file taken out, it fails on the seed corpus, before mutating anything.

The `extract_7z` fuzz target does the same for 7z, seeded with `testdata/7z` behind a byte of options, the archive opened with small limits on what it may allocate and a password, so that the AES coder's paths are taken. Its first three minutes, 3.1 million inputs, found nothing. Half its inputs, by their length, take three threads, which decode folders at once: then what is left must be no more than what was told written, as files other threads were writing when one failed are removed. Its first 150 s with threads, 820,000 inputs, found nothing.

The `extract_tar` fuzz target does the same for tar, seeded with Go's test archives behind a choice of options, a hard link's file counted once. Its first three minutes found that the progress totals left out what links written as files write (a symbolic link's target, a hard link's copy), so that progress passed its total; they count it now, which `tests/tar.rs` checks. The next three minutes, 5.4 million inputs, found nothing, and three more, 3.6 million, once each reading went on to the end of the stream.

## What comes next

- **Links that lead out through what is already in the destination.** With `Links::Inside`, a target is checked against the archive's own links; one through a link that was there before, in a destination that is not empty, is not looked at. Nothing is written through it, as directories are opened without following links.
