# hivepack

Read and write archives and compressed files in Rust: one library for many formats, in the spirit of [libarchive](https://github.com/libarchive/libarchive).

> **Status:** version 0.11.0, on crates.io as one crate, [`hivepack`](crates/hivepack). Before 1.0 a minor release may change an API: see [CHANGELOG.md](CHANGELOG.md). Security reports: [SECURITY.md](SECURITY.md).

```toml
[dependencies]
hivepack = "0.11"                                                           # every format but RAR
# hivepack = { version = "0.11", default-features = false, features = ["zip", "zstd"] }  # only these
# hivepack = { version = "0.11", features = ["rar"] }                       # RAR too, under UnRAR's license
```

## 📦 Modules

Each is a module of the crate behind a feature of the same name, and the ones it needs come with it. Each keeps the license of what it is ported from, in its folder: see [crates/hivepack/LICENSE.md](crates/hivepack/LICENSE.md).

| Module | What it is | Status |
|---|---|---|
| [`hivepack::sevenz`](crates/hivepack/src/sevenz) | Reading 7z archives in safe Rust, ported from the LZMA SDK's 7z decoder (7-Zip 26.05), and writing them | Opens what the SDK opens and decodes what it decodes, Copy, LZMA, LZMA2 and PPMd with their filters and BCJ2, with its answers and error numbers, and past it what 7-Zip's program reads: any graph of coders, with Deflate, Deflate64, BZip2, Zstandard and AES with a password; folders are read in pieces, so that a solid block of any size takes little memory; extracted by `hivepack::extract` |
| [`hivepack::age`](crates/hivepack/src/age) | Decrypting and encrypting [age](https://age-encryption.org) files in safe Rust, ported from age v1.3.2, the reference implementation in Go | Decrypts with passphrases, X25519 keys, post-quantum keys and SSH Ed25519 keys (passphrase-protected ones too), armored or not, with age's outcomes on all 147 of C2SP's test vectors and on files age encrypts and that are then damaged. Encrypts with passphrases and to those keys, and makes keys, byte for byte as age does given the same random bytes. SSH RSA keys come later |
| [`hivepack::appimage`](crates/hivepack/src/appimage) | AppImages: where the program ends, ported from AppImage's type 2 runtime, and the image after it | Finds the end of 32-bit and 64-bit ELF programs of either byte order as the runtime does, and opens a type 2 AppImage's SquashFS image there; type 1 is ISO 9660 |
| [`hivepack::ar`](crates/hivepack/src/ar) | ar archives and Debian packages in safe Rust, ported from libarchive 3.8.10's ar reader | Reads GNU/SVR4 and BSD archives, their long names and symbol tables, with libarchive's headers, data and errors on its test archive, archives its writers make and thousands made and damaged by the tests; `hivepack::open` opens a `.deb` to the files it installs. Writing is not ported |
| [`hivepack::bzip2`](crates/hivepack/src/bzip2) | bzip2 in safe Rust, ported from libbzip2 1.0.8: the same output, at the same speed | Compresses with libbzip2's output, byte for byte, at every block size and work factor, and decompresses with its results, fast or small, randomised blocks included, both at about its speed; beside the port, compresses in threads as pbzip2 does, streams one after the other that `hivepack::open` decodes in threads too |
| [`hivepack::cpio`](crates/hivepack/src/cpio) | cpio archives and RPM packages' payloads in safe Rust, ported from libarchive 3.8.10's cpio reader and RPM filter | Reads odc, newc, crc, afio's large headers and binary cpio in both byte orders, with symbolic and hard links and the search for a header after garbage, with libarchive's headers, warnings, data and errors on its test archives, archives its writers make and tens of thousands of damaged ones; takes the lead and headers off RPM packages as libarchive does. Writing is not ported |
| [`hivepack::crypto`](crates/hivepack/src/crypto) | The cryptography of hivepack's formats, behind one small interface, from crates many others depend on: `aes`, `sha2`, `chacha20poly1305`, `curve25519-dalek`, `scrypt` and others | No cryptography of its own and no `unsafe` code of its own; compared with nettle and Go's `x/crypto`, and against the published vectors |
| [`hivepack::deflate`](crates/hivepack/src/deflate) | Deflate, zlib and gzip in safe Rust, ported from zlib 1.3.2: the same output, at the same speed | Compresses with zlib's output, byte for byte, and decompresses with its results and messages, compressing at about its speed and decompressing at 1.2–2.0× it. Decodes Deflate64 as zlib's `contrib/infback9` does; beside the port, compresses in threads as pigz does, one gzip stream, pigz's byte for byte; and a port of libdeflate 1.26's compressor, its streams byte for byte at levels 0 to 12 |
| [`hivepack::extract`](crates/hivepack/src/extract) | Extracting archives to disk, safe by default: nothing outside the destination, through links, over what is there, or past limits | Extracts ZIP, tar, 7z, RAR (with its feature `rar`, under UnRAR's license), cpio (RPM packages' payloads among them) and XAR archives (macOS packages and `.xip` files, their payloads expanded as `pkgutil --expand-full` does), ISO 9660 images, UDF volumes and SquashFS images (snaps), refusing unportable names, the same path twice, links and overlapping data, writing by handle and counting what is written; tar, cpio, XAR and ISO read twice, to check everything before writing. RAR comes later |
| [`hivepack::iso`](crates/hivepack/src/iso) | ISO 9660 images in safe Rust, ported from libarchive 3.8.10's reader | Reads ISO 9660 with Rock Ridge, Joliet, files in several extents and zisofs, with libarchive's headers, warnings, data and errors, on its test images, images its writer makes and tens of thousands of damaged ones. UDF and writing are not ported |
| [`hivepack::lz4`](crates/hivepack/src/lz4) | LZ4 in safe Rust, ported from liblz4 1.10.0: blocks, frames and `.lz4` files | Compresses blocks and frames with liblz4's output, byte for byte, at every acceleration and level, with dictionaries, call by call; decodes blocks with liblz4's results, error positions included, and the same bytes in the output; decodes frames call by call as `LZ4F_decompress` does; writes `.lz4` files as liblz4 does and reads them, legacy ones included, as `lz4 -d` does; decodes at 0.75× liblz4's speed, or 0.96× with its `unsafe-fast` feature |
| [`hivepack::lzo`](crates/hivepack/src/lzo) | LZO1X decompression in safe Rust, ported from lzokay's decompressor, with the results of liblzo2 2.10's `lzo1x_decompress_safe`: the blocks of SquashFS images made with `-comp lzo` | Decodes raw LZO1X blocks with liblzo2's bytes, and on damaged blocks its errors and the bytes it leaves in the output; 1.48× liblzo2's speed on average on Silesia's blocks by `lzo1x_1` and 1.32× by `lzo1x_999` (0.97× at worst); no compression, no `.lzo` files |
| [`hivepack::memory`](crates/hivepack/src/memory) | How much memory the program may still take, for an application to choose its coders' threads under it; off by default, as it is not a format | Measures what is available on Linux (`MemAvailable`, each control group from the program's own up, `ulimit -v` and `-d`), Windows (available memory, the job object's limits) and macOS (free, file and purgeable pages), and says which bound applied; a `Budget` shares a part of it between jobs at once, each holding the most threads whose estimate fits until it ends. See [docs/memory.md](docs/memory.md#measuring-what-is-available) |
| [`hivepack::open`](crates/hivepack/src/open) | Opening what hivepack reads through the layers around it: age, zstd, xz, lzip, .lzma, LZ4, gzip, bzip2, pbzx, RPM packages and Debian packages, found by their first bytes and stacked, then the container told (SquashFS among them) | Opens `.tar.zst.age`, `.iso.xz`, `.rpm`, `.deb`, `.pkg` and any stack of these layers with hivepack's ports, each read as its tools read it, a passphrase asked for once however often the file is read; a tar, cpio or XAR archive or ISO 9660 image under them extracts with `hivepack::extract`, which reads the stream to its end to check it before writing; UDF volumes are told too |
| [`hivepack::rar`](crates/hivepack/src/rar) | Reading RAR archives in safe Rust, ported from RARLAB's UnRAR 7.3.2, under UnRAR's license: it reads RAR and never writes it | Reads what UnRAR reads, as UnRAR does, broken archives included: the headers of RAR 1.4 to 7, every algorithm and cipher, volumes, comments and QuickOpen records, with UnRAR's fields, positions and exit codes on the archives of four other projects and hundreds of thousands of damaged copies |
| [`hivepack::sign`](crates/hivepack/src/sign) | Signing files with SSH Ed25519 keys, in the format of `ssh-keygen -Y sign` | Signs any file whole, beside it, with `ssh-keygen`'s output, byte for byte, and checks what `ssh-keygen` signs. Hybrid keys of Ed25519 and ML-DSA-65 too, which only it checks. RSA and ECDSA keys are not taken |
| [`hivepack::squashfs`](crates/hivepack/src/squashfs) | Reading SquashFS images in safe Rust, ported from squashfuse 0.6.5's library: snap packages and the images in AppImages | Reads SquashFS 4.0 as squashfuse does: every inode type, basic and extended, directories with their index, fragments, holes, hard links, owners, extended attributes and the export table, compressed with zlib, LZMA, LZO, xz, LZ4 or zstd, or stored. What it reads is squashfuse's, line for line, on 31 images mksquashfs 4.6.1 makes (all but its LZO ones), a snap and an AppImage, and thousands of damaged copies |
| [`hivepack::tar`](crates/hivepack/src/tar) | tar archives in safe Rust, ported from Go 1.27.2's `archive/tar` | Reads V7, USTAR, PAX, GNU and STAR archives, PAX records, GNU long names and sparse files included, with Go's headers, data and errors on Go's test archives, archives Go writes and thousands of damaged ones; writes USTAR, PAX and GNU, every byte and error the same as Go's |
| [`hivepack::udf`](crates/hivepack/src/udf) | Reading UDF volumes in safe Rust, ported from NetBSD's UDF file system (`sys/fs/udf`): DVD, Blu-ray and disk images | Reads UDF 1.02 to 2.60 on physical, sparable, virtual (VAT) and metadata partitions, with blocks of 512 to 4096 bytes, as NetBSD mounts them, but where NetBSD loops, crashes or reads wrong; the same as Linux's udf file system on 36 images mkudffs, genisoimage and its tests make; extracted by `hivepack::extract` |
| [`hivepack::xar`](crates/hivepack/src/xar) | XAR archives (macOS `.pkg` and `.xip` files) in safe Rust, ported from libarchive 3.8.10's reader, with the parts of libxml2 2.15.4 it reads the table of contents with | Reads every file with its metadata, extended attributes, links and data (stored, gzip, bzip2, lzma, xz; MD5, SHA-1, SHA-256 and SHA-512 checked), with libarchive's headers, warnings, data and errors, on its test archives, archives its writer, macOS's `xar` and `pkgbuild` make, archives the tests make, and tens of thousands of damaged ones. Writing is not ported |
| [`hivepack::xz`](crates/hivepack/src/xz) | XZ and LZMA in safe Rust, ported from liblzma of XZ Utils 5.8.4: the same output, at the same speed | Compresses `.xz`, `.lzma`, and raw LZMA1 and LZMA2 with liblzma's output, byte for byte, with every preset, option and match finder, at about its speed; decompresses those and `.lz` with its results, call by call, at 1.23–1.69× the speed of liblzma's C and 0.89–1.03× of its x86-64 assembly; with the delta and BCJ filters, and in threads for `.xz` |
| [`hivepack::zip`](crates/hivepack/src/zip) | ZIP archives in safe Rust, the container logic ported from libzip 1.12.1 | Opens archives, reads their headers, and reads stored, deflated, bzip2, LZMA, XZ, Zstandard, Deflate64 and PPMd entries with libzip's rules and errors; edits names, comments, times and attributes, deletes entries, adds and replaces data, stored, deflated, bzip2, LZMA, XZ or Zstandard, and writes the archive as libzip does, byte for byte; encrypts and decrypts ZipCrypto and WinZip AES; reads split archives, which libzip refuses, compared with 7-Zip. The rest compared with libzip, and 174 of libzip's own tests pass through the port's `ziptool` |
| [`hivepack::zstd`](crates/hivepack/src/zstd) | Zstandard in safe Rust, ported from libzstd 1.5.7: the same output, at the same speed | Decompresses, in one call or streaming, with the same output and errors as libzstd, at 0.75–0.95× its speed. Compresses at every level, in one call or streaming, with dictionaries, on several threads, with libzstd's frames. Trains dictionaries as libzstd does |

Every module forbids `unsafe` code; the exceptions, the `unsafe-fast` features of `hivepack::zstd`, `hivepack::lz4`, `hivepack::deflate` and `hivepack::xz`, and the system calls of `hivepack::memory` on Windows and macOS, are off by default (see [docs/unsafe.md](docs/unsafe.md)). Dependencies with `unsafe` code are in three crates only: cap-std and, on macOS, rustix in `hivepack::extract`, until the standard library can open files from a directory's handle and set extended attributes; the cryptography's crates in `hivepack::crypto`; and rustix, windows-sys or libc, by system, in `hivepack::memory`, so "in safe Rust" above means a crate's own code. The rules are in [docs/safety.md](docs/safety.md), and how the ports follow the official libraries is in [docs/porting.md](docs/porting.md) (zstd), [docs/deflate.md](docs/deflate.md) (zlib), [docs/bzip2.md](docs/bzip2.md) (libbzip2), [docs/lz4.md](docs/lz4.md) (liblz4), [docs/lzo.md](docs/lzo.md) (lzokay, with liblzo2's results), [docs/xz.md](docs/xz.md) (liblzma), [docs/zip.md](docs/zip.md) (libzip), [docs/crypto.md](docs/crypto.md) (what the cryptography comes from) and [docs/age.md](docs/age.md) (age), [docs/tar.md](docs/tar.md) (Go's archive/tar), [docs/7z.md](docs/7z.md) (the LZMA SDK), [docs/iso.md](docs/iso.md), [docs/cpio.md](docs/cpio.md), [docs/ar.md](docs/ar.md) and [docs/xar.md](docs/xar.md) (libarchive, and libxml2 for XAR), and [docs/udf.md](docs/udf.md) (NetBSD's UDF).

## ⚡ Speed

Each port is timed against the library it comes from, on the same data, and every tool is in `tools/`. Above 1× the port is faster. Each module's README has its table, and how it was measured.

| Crate | Against | Where it is ahead or even | Where it is behind |
|---|---|---|---|
| [`hivepack::bzip2`](crates/hivepack/src/bzip2#speed) | libbzip2 1.0.8 | compression 1.05×, decompression 1.01× | |
| [`hivepack::deflate`](crates/hivepack/src/deflate#speed) | zlib 1.3.2, libdeflate 1.26's compressor | compression 0.99×, decompression 1.29–1.61×; libdeflate's level 12 1.03–1.05× | libdeflate's levels 1 to 9 0.87–0.93× |
| [`hivepack::xz`](crates/hivepack/src/xz#speed) | liblzma 5.8.4 | compression 1.02×, decompression 1.44× against its C | decompression 0.94× against its x86-64 assembly |
| [`hivepack::lzo`](crates/hivepack/src/lzo#speed) | liblzo2 2.10's `lzo1x_decompress_safe` | decompression 1.48× of `lzo1x_1`'s blocks (1.11–1.63×), 1.32× of `lzo1x_999`'s (0.97–1.53×) | |
| [`hivepack::lz4`](crates/hivepack/src/lz4#speed) | liblz4 1.10.0 | decoding 0.96× with `unsafe-fast`, compression 0.95× at level 1 | decoding 0.75× without it, high compression 0.74–0.98× |
| [`hivepack::zstd`](crates/hivepack/src/zstd#speed) | libzstd 1.5.7 | level 19 0.96× | decompression 0.78× (0.82× with `unsafe-fast`), levels 1 and 3 0.85×, levels 9 and 12 0.45–0.56× (0.54–0.71×) |

| [`hivepack::sevenz`](crates/hivepack/src/sevenz#speed) | LZMA SDK 26.05, 7-Zip | LZMA and LZMA2 1.34–1.48× against C, Deflate 1.84×, AES-256 behind a compressor 1.38–1.44× | PPMd 0.84–0.91×, BZip2 0.61×, AES-256 with Copy 0.63× |
| [`hivepack::squashfs`](docs/squashfs.md#speed) | squashfuse 0.6.5; squashfs-tools 4.6.1's `unsquashfs` for extracting | reading gzip 1.52×, LZO 1.45×, xz 0.96× | reading a snap (xz) 0.94×, LZMA 0.93×, zstd 0.78–0.82×, nothing compressed 0.76×, LZ4 0.73×; extracting a snap on 32 threads 0.68× `unsquashfs -p 32` |
| [`hivepack::tar`](crates/hivepack/src/tar#speed) | Go 1.27.2's `archive/tar` | going through entries 1.48–2.61×, reading data 1.02–2.00×, seeking past data 2.05×, writing entries 2.03–3.11×, big entries 1.05× | |
| [`hivepack::age`](crates/hivepack/src/age#speed) | age v1.3.2, in Go | X25519 2.23–2.35×, scrypt 1.02–1.28×, a big file in ASCII armor 1.29× | a big file's payload 0.40× |
| [`hivepack::rar`](crates/hivepack/src/rar#speed) | UnRAR 7.3.2 | RAR 4 and RAR 5 without a password, 0.83–1.53× over three machines, RAR 5 with a password 1.28–1.74× | PPMd 0.74–0.93×, RAR 4 with a password 0.87–1.08× |

**Measured on,** in October and November 2026, with safe code unless it says otherwise:

- `hivepack::zip`, `hivepack::sevenz`, `hivepack::tar` and `hivepack::age`: AMD Ryzen 9 9950X (16 cores, x86-64), 45 GiB of memory, Ubuntu 26.04 with Linux 7.0 and the `powersave` governor, rustc 1.99.1 in the workspace's release profile; the libraries built with GCC 15.2.
- Each of them also on GitHub's runners, Linux x86-64, Windows x86-64 and macOS arm64, with and without `unsafe-fast` where a crate has it, last on November 10, 2026: see their READMEs. `hivepack::rar` only there, on `testdata/rar`. `.github/workflows/bench.yml` runs each format on those three.
- `hivepack::bzip2`, `hivepack::deflate`, `hivepack::lz4`, `hivepack::lzo`, `hivepack::xz` and `hivepack::zstd`: an AMD Ryzen 9 9950X (x86-64, Linux).
- `hivepack::squashfs`: the same machine, on KeeWeb 1.18.7's snap, appimagetool 1.9.1's AppImage and trees mksquashfs made with each compressor, read file by file against squashfuse, and extracted into tmpfs against `unsquashfs`, both built from their releases with the same compressors.

These are snapshots of one machine or two, on the Silesia corpus but for SquashFS: run the tools to see your own. How a reference is built matters: liblzma and libzstd have x86-64 assembly, and the usual builds of 7-Zip and of libzip's crypto libraries go further than the ones timed here, as each README says. `hivepack::ar`, `hivepack::appimage`, `hivepack::iso`, `hivepack::udf`, `hivepack::open` and `hivepack::extract` (but for SquashFS, above) have no such comparison yet.

## 🦀 Rust versions

- **Oldest supported: 1.89**, `rust-version` in `Cargo.toml`, which CI checks.
  It is a promise to the crates' users: raised only when the code needs
  something newer, never to a Rust less than a year old, and in a minor
  release with a line in its notes.
- **Development:** `rust-toolchain.toml` pins the stable Rust that formats,
  lints, documents and tests, so a new Rust never turns CI red on its own. It
  is raised by hand every second Rust release (about every twelve weeks), once
  that release is two weeks old, in a pull request of its own, together with
  the nightly that Miri and cargo-fuzz use (`NIGHTLY` in
  `.github/workflows/ci.yml`).
- **Newer Rust:** a weekly workflow (`.github/workflows/newer-rust.yml`) lints
  and tests with the latest stable and beta, which users may build with before
  the pin is raised. A failure there warns; it blocks nothing.
